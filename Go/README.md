# Go 项目标准

本目录用于沉淀可复用的 Go 项目约定，帮助项目保持一致的代码质量、审查方式和变更记录。

## 文档

- [Go 编码标准](go/coding-standard.md)：代码组织、错误处理、并发、资源管理和测试约定。
- [Go Code Review 检查清单](go/review-checklist.md)：按正确性、风险和验证证据审查改动。
- [Pull Request 模板](templates/pull-request.md)：记录改动目的、验证结果、风险和回滚方式。

## 使用方式

1. 新项目先采用编码标准，并根据项目架构补充必要约定。
2. 提交改动前，按 Review 检查清单自查并运行项目已有的格式化、静态检查、测试和构建流程；CI 至少应覆盖这些检查，具体命令由项目确定。
3. 提交 Pull Request 时填写模板。没有运行某项检查时，说明原因；不要把未执行的检查写成已通过。
4. 对认证、权限、数据迁移、并发控制、发布和 CI 等高影响改动，安排有相应上下文的人审查，并写清验证和回滚办法。

## 标准的维护原则

- 规则应能指导实现或检查结果；对纯个人偏好的要求应标为建议，而非强制标准。
- 优先将反复出现的问题转化为文档、自动检查或测试。
- 每次事故或回滚后，复盘现有约定和检查是否能更早发现问题，并按证据改进。
- 项目可以增加更严格的约定，但应说明适用范围和原因；如有冲突，以项目明确记录的约定为准。
